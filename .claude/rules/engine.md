The orchestrator: previews, worktrees, builds, devices, and everything that outlives the process.

Hardest rules:

- **Anything spawned detached must stamp an env marker** a later boot can hunt for. An in-memory `Map` is not an owner — it is empty in a fresh process while the children are still running. Three of four detached resources leaked; one reached 36 orphans at 418% CPU, which starved the emulators (CPU-bound QEMU) while iOS stayed fine. → `invariants.test.ts` "marks every long-lived detached spawn". That check is **per file, not per spawn** — it asks whether the file stamps a marker anywhere, because Metro stamps indirectly through a `baseEnv()` helper. So a SECOND detached spawn added to a file that already stamps one passes it silently (verified by mutation). If you add a spawn next to an existing one, nothing will tell you it is unstamped.
- **Bookkeeping goes AFTER the effect it records.** A pooled AVD's tenancy was recorded before the `-wipe-data` boot, so a boot that threw left the new app as owner, the retry skipped the wipe, and the previous tenant's storage was handed across owner scopes.
- **Every new `await` widens a window.** Ask what was true between the two lines that is no longer true. Putting the Metro reap ahead of `liveDeviceHandles()` did exactly this.
- **An empty result and a failed lookup must not be the same value.** `loadAppsSafe()` returned `[]` on any failure and `app add` then wrote a file containing only the new app. `AndroidManager.describe` returned `""` for a failed `uiautomator dump`, which an agent reads as "the screen is empty". For every new `catch {}`, `?? []`, `|| false` or unchecked exit code: **which direction does this fail in, and is that the safe one?**
- **Ask adb, not your own bookkeeping.** Deckhand's port set knows nothing about emulators it did not start, and `adb wait-for-device` answers instantly against a stranger's — or a dying one.

**A phone is borrowed hardware.** Waited for, never booted, wiped, killed or reaped, never a setting changed, one live preview at a time. On it deckhand may install, update, `pm clear` or uninstall ONLY the preview's registered app, and only through `RegisteredApp` (`devices/androidPhone.ts`) on Android or `IphoneApps` (`devices/iphoneApps.ts`) on an iPhone, whose one guard refuses any other package or bundle id before adb or devicectl runs. An iPhone's UDID lives on `record.serial`, never `record.udid`: every simulator path (`simctl shutdown`/`delete`, the reaper) keys on `udid`, so a phone cannot reach one. Its WDA runner and `iproxy` belong to the server, not the preview: teardown stops the app and the syslog only. → `iphoneApps.test.ts` "refuses to install an artifact that holds another app", `preview.test.ts` "installs the environment's EAS .ipa, starts syslog before a launch with -KEY value, and verifies the environment from the app log" → `androidPhone.test.ts` "refuses to uninstall, clear, stop, install or open a link in any other package — and runs no adb for it", `android.test.ts` "refuses a physical serial before sending anything to it", `preview.test.ts` "never hands a physical serial to the reaper or the emulator teardown, and keeps its stream at the boot sweep"

**WDA serves nothing off the phone.** WebDriverAgent has no authentication, so it runs only from a per-phone loopback copy of the `.xctestrun` (USE_IP=127.0.0.1, written aside and renamed into place, so a running xcodebuild never reads it unbound), only at WDA 16.15.3 or newer (the first whose MJPEG honours USE_IP), and a Wi-Fi probe calls any accepted connection exposed. → `wdaRunner.test.ts` "never leaves a started runner's copy unbound while another start rewrites it", `wdaRunner.test.ts` "refuses a WDA too old to keep its screen stream off Wi-Fi, and stops the runner it started", `wdaRunner.test.ts` "calls a port that streams forever exposed, with the real curl"

**Borrow-never-own.** A `path` app is the developer's working copy: never wipe it, never remove it, never commit in it, never rewrite a tracked file. The install path has no updating fallback there for exactly this reason.
